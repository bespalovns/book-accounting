# Информационная подсистема учета книг

## Состав

- backend — Flask, веб-интерфейс и API.
- android — отдельное Android-приложение на Kotlin и XML.
- PostgreSQL — общая база данных сайта и Android.

## Возможности

- Учет книг, авторов и издательств.
- Добавление, просмотр, редактирование и удаление записей.
- Поиск книг и фильтр наличия.
- Проверка ISBN и запрет удаления связанных справочников.

## Локальный запуск сервера

1. Открыть backend.
2. Установить зависимости:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. Создать .env по образцу .env.example.
4. Указать параметры существующей PostgreSQL.
5. Для новой пустой БД создать таблицы по sql/schema.sql.
   Этот файл рассчитан на ранее созданную роль book_app.
   Повторно выполнять его в заполненной БД не нужно.
6. Запустить:

   ```powershell
   python app.py
   ```

7. Открыть http://127.0.0.1:5000.

## Android

Открыть папку android в Android Studio.
Дождаться Gradle Sync и запустить приложение.

Для эмулятора локальный сервер доступен по адресу
http://10.0.2.2:5000.

Для телефона используется HTTPS-адрес размещенного сервера.
Адрес задается в ApiClient.kt.

## Сборка APK

Из папки android:

```powershell
.\gradlew.bat assembleDebug
```

Результат: app/build/outputs/apk/debug/app-debug.apk.

## Использование размещенной версии

Python-сервер и сайт размещены на Render, база PostgreSQL — в Neon.
Для работы сайта и готового APK запускать `app.py` на компьютере не требуется.

На сайте и в Android-приложении используются одинаковые логин и пароль.
Данные входа передаются преподавателю отдельно и не публикуются в репозитории.

После простоя бесплатный сервер может запускаться около минуты.
Изменения, внесенные на сайте, появляются в приложении после обновления списка, и наоборот.

Проверка сервера: https://book-accounting.onrender.com/healthz  
Проверка базы после входа: https://book-accounting.onrender.com/api/health

Ожидаемый ответ обеих проверок:

```json
{"status":"ok"}
```

## Установка APK на телефон

Требуется Android 8.0 или новее и доступ в интернет.

1. Получить APK у автора либо скачать прикрепленный файл из раздела [Releases](https://github.com/bespalovns/book-accounting/releases), когда релиз будет опубликован.
2. Перенести файл `app-debug.apk` на телефон и открыть его.
3. При необходимости разрешить установку из используемого источника.
4. Установить приложение, ввести данные входа и выбрать раздел.

Сборка `assembleDebug` создает APK, подписанный отладочным ключом, для установки и демонстрации. Для сборки запуск эмулятора не требуется.

После успешной авторизации при возвращении на главный экран блок входа скрывается.
Данные входа хранятся только в памяти процесса приложения. После завершения процесса потребуется повторный вход.
Состояние экранов каталога сохраняется при повороте устройства.

Текущий `BASE_URL` в `ApiClient.kt` — `https://book-accounting.onrender.com`.
Для проверки локального сервера через эмулятор нужно заменить его на `http://10.0.2.2:5000` и пересобрать приложение.
Этот адрес предназначен для эмулятора, а не физического телефона.
Перед сборкой APK для преподавателя следует вернуть HTTPS-адрес Render.

## Дополнения к локальной настройке

### Виртуальное окружение

Из папки `backend` в Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

После настройки базы и `.env` проверить подключение и запустить сервер:

```powershell
.\.venv\Scripts\python.exe check_database.py
.\.venv\Scripts\python.exe app.py
```

### Образец .env

Файл `.env` должен находиться в папке `backend`, рядом с `db.py`.
Если `.env.example` отсутствует, можно создать `.env` по этому образцу:

```dotenv
DATABASE_URL=

DB_HOST=localhost
DB_PORT=5432
DB_NAME=book_accounting
DB_USER=book_app
DB_PASSWORD=

APP_ENV=local
APP_USERNAME=
APP_PASSWORD=
PUBLIC_URL=
```

Для локальной базы заполнить `DB_PASSWORD` паролем роли `book_app`.
Для удаленной базы заполнить `DATABASE_URL` настоящей строкой подключения PostgreSQL.
Если `DATABASE_URL` заполнена, отдельные переменные `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` и `DB_PASSWORD` не используются.

Для локальной работы без авторизации оставить `APP_USERNAME` и `APP_PASSWORD` пустыми.
Чтобы включить авторизацию, заполнить оба значения и перезапустить сервер.
Настоящий `.env` с паролями не должен попадать на GitHub.

### Создание новой локальной базы

Только для новой установки: подключиться администратором PostgreSQL к базе `postgres` и создать роль, заменив пароль на собственный:

```sql
CREATE ROLE book_app
WITH LOGIN PASSWORD 'ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ';
```

Затем выполнить отдельно, вне блока транзакции:

```sql
CREATE DATABASE book_accounting OWNER book_app;
```

Подключиться к новой базе под пользователем `book_app` и выполнить `backend/sql/schema.sql`.
Файл создает таблицы и ограничения, но не добавляет записи. Данные можно внести через интерфейс.
Для уже заполненной базы Neon эти действия повторять не нужно.

## Настройки размещения

| Параметр Render | Значение |
|---|---|
| Ветка | `main` |
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Health Check Path | `/healthz` |

Start Command:

```bash
gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120
```

Переменные окружения задаются в панели Render:

- `DATABASE_URL` — строка подключения к Neon.
- `APP_ENV=production`.
- `APP_USERNAME` — логин приложения.
- `APP_PASSWORD` — пароль приложения длиной минимум 16 символов.
- `PUBLIC_URL=https://book-accounting.onrender.com`.

Пароли базы и приложения не записываются в исходники или README.
