# Информационная подсистема учета книг

## Состав

- backend — Flask, веб-интерфейс и API.
- android — отдельное Android-приложение на Kotlin и XML.
- PostgreSQL — общая база данных сайта и Android.

## Возможности

- Учет книг, авторов и издательств.
- Добавление, просмотр, редактирование и удаление записей.
- Поиск книг и фильтр наличия.
- Проверка ISBN и запрет удаления связанных справочников.

## Локальный запуск сервера

1. Открыть backend.
2. Установить зависимости:

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. Создать .env по образцу .env.example.
4. Указать параметры существующей PostgreSQL.
5. Для новой пустой БД создать таблицы по sql/schema.sql.
   Этот файл рассчитан на ранее созданную роль book_app.
   Повторно выполнять его в заполненной БД не нужно.
6. Запустить:

   ```powershell
   python app.py
   ```

7. Открыть http://127.0.0.1:5000.

## Android

Открыть папку android в Android Studio.
Дождаться Gradle Sync и запустить приложение.

Для эмулятора локальный сервер доступен по адресу
http://10.0.2.2:5000.

Для телефона используется HTTPS-адрес размещенного сервера.
Адрес задается в ApiClient.kt.

## Сборка APK

Из папки android:

```powershell
.\gradlew.bat assembleDebug
```

Результат: app/build/outputs/apk/debug/app-debug.apk.

## Использование размещенной версии

Python-сервер и сайт размещены на Render, база PostgreSQL — в Neon.
Для работы сайта и готового APK запускать `app.py` на компьютере не требуется.

На сайте и в Android-приложении используются одинаковые логин и пароль.

После простоя бесплатный сервер может запускаться около минуты.
Изменения, внесенные на сайте, появляются в приложении после обновления списка, и наоборот.

Проверка сервера: https://book-accounting.onrender.com/healthz  
Проверка базы после входа: https://book-accounting.onrender.com/api/health

Ожидаемый ответ обеих проверок:

```json
{"status":"ok"}
```
